# Laporan Audit Keamanan Aplikasi Berbasis OWASP Top 10 (2021) — MFLS
**Aplikasi:** MNC University Future Leader Scholarship (MFLS)  
**Tanggal Audit:** 4 November 2026  
**Standar Acuan:** Open Web Application Security Project (OWASP) Top 10 - 2021  
**Metodologi:** Static Application Security Testing (SAST), Dynamic Analysis Lingkungan Staging, & Code Architecture Review  
**Prinsip Audit:** Read-Only Audit (Tidak ada perubahan kode aplikasi pada sesi pengujian ini)

---

## 1. Ringkasan Eksekutif

Audit keamanan independen ini dilakukan terhadap basis kode portal penerimaan beasiswa **MNC University Future Leader Scholarship (MFLS)** untuk mengidentifikasi celah kerentanan, kesalahan konfigurasi, dan risiko eksposur data pendaftar mengacu pada standar global **OWASP Top 10: 2021**.

### Matriks Distribusi Temuan Keamanan:
| Kategori Risiko | Jumlah Temuan | Area Terdampak Utama |
|---|:---:|---|
| 🔴 **Critical** | 2 | Eksposur data pendaftar tanpa autentikasi, Eksekusi migrasi publik |
| 🟠 **High** | 1 | Komponen pihak ketiga berkerentanan publik (*dompdf / laravel*) |
| 🟡 **Medium** | 4 | PRNG tidak aman pada OTP, Token reset plaintext, Bypass rate limiter via User-Agent, Rute debug semi-terbuka |
| 🔵 **Low / Info** | 3 | Absensi security headers di middleware Laravel, Tidak adanya audit log kegagalan login, Sanitasi XSS konten berita |

### Temuan Paling Kritis yang Membutuhkan Atensi Segera:
1. **Eksposur Data Sensitif Tanpa Autentikasi (`/debug-candidates`):** Rute ini dapat diakses oleh siapa saja di internet tanpa login dan membocorkan data pendaftar nyata (nama lengkap, ID, status beasiswa, status wawancara, nilai).
2. **Endpoint Migrasi Basis Data Publik (`/debug-migrate`):** Siapa pun dapat memicu `php artisan migrate --force` secara langsung dari peramban web tanpa autentikasi, yang berpotensi merusak skema data dan menyebabkan *Denial of Service*.

### A01:2021 – Broken Access Control

#### Temuan 1.1: Rute Debug Publik Membocorkan Data Pendaftar (PII Exposure)
- **Tingkat Risiko:** 🔴 **CRITICAL** (CVSS: 9.1)
- **Lokasi Kode:** `routes/web.php` (Baris 346–373)
- **Bukti Implementasi:**
  ```php
  Route::get('/debug-candidates', function () {
      $alfans = \App\Models\Akun::where('nama', 'like', '%alfan%')->with(['peserta.daftar', 'peserta.penilaianAkademiks'])->get();
      $raihans = \App\Models\Akun::where('nama', 'like', '%raihan%')->with(['peserta.daftar', 'peserta.penilaianAkademiks'])->get();
      return response()->json([
          'alfans' => $alfans->map(fn($a) => [ ... ]),
          'raihans' => $raihans->map(fn($a) => [ ... ])
      ]);
  });
  ```
- **Dampak:** Siapa saja tanpa login dapat mengakses `GET /debug-candidates` untuk mengunduh identitas lengkap pendaftar, nilai rekomendasi, status seleksi, dan data beasiswa.
- **Rekomendasi Perbaikan:** Hapus rute ini sepenuhnya dari `routes/web.php` pada lingkungan produksi, atau bungkus dalam middleware `auth` dan `role:admin`.

#### Temuan 1.2: Rute Debug Migrasi Database Terbuka untuk Publik
- **Tingkat Risiko:** 🔴 **CRITICAL** (CVSS: 8.6)
- **Lokasi Kode:** `routes/web.php` (Baris 337–344)
- **Bukti Implementasi:**
  ```php
  Route::get('/debug-migrate', function () {
      try {
          \Illuminate\Support\Facades\Artisan::call('migrate', ["--force" => true]);
          return "<pre>" . \Illuminate\Support\Facades\Artisan::output() . "</pre>";
      } catch (\Exception $e) {
          return "Error: " . $e->getMessage();
      }
  });
  ```
- **Dampak:** Penyerang dapat memicu eksekusi perintah migrasi basis data secara sewenang-wenang tanpa hak akses.
- **Rekomendasi Perbaikan:** Hapus rute ini dari file web routes. Jalankan migrasi hanya melalui CLI/SSH server terproteksi (`php artisan migrate --force`).

#### Temuan 1.3: Akses Parsial Data Penilaian Beasiswa oleh Akun Pendaftar
- **Tingkat Risiko:** 🟡 **MEDIUM**
- **Lokasi Kode:** `routes/debug.php` (Baris 7–34)
- **Bukti Implementasi:**
  ```php
  Route::get('/debug-beasiswa-100', function () { ... })->middleware('auth');
  ```
- **Dampak:** Rute dilindungi middleware `auth`, namun tidak memeriksa role. Akun dengan role `pendaftar` biasa yang telah login dapat melihat sampling penilaian akademik dan rekomendasi beasiswa peserta lain.
- **Rekomendasi Perbaikan:** Ubah middleware menjadi `->middleware(['auth', 'role:admin'])` atau hapus file debug ini.

### A02:2021 – Cryptographic Failures

#### Temuan 2.1: Generator Kode OTP Menggunakan Fungsi Pseudo-Random Tidak Aman
- **Tingkat Risiko:** 🟡 **MEDIUM**
- **Lokasi Kode:** `app/Http/Controllers/AuthController.php` (Baris 153 & 276)
- **Bukti Implementasi:**
  ```php
  $otpCode = rand(100000, 999999);
  ```
- **Dampak:** Fungsi `rand()` bawaan PHP bukan *Cryptographically Secure Pseudo-Random Number Generator* (CSPRNG). Bilangan yang dihasilkan rentan diprediksi melalui algoritma *seed analysis*.
- **Rekomendasi Perbaikan:** Ganti fungsi dengan CSPRNG standar PHP:
  ```php
  $otpCode = random_int(100000, 999999);
  ```

#### Temuan 2.2: Penyimpanan Token Reset Password & OTP dalam Format Plaintext
- **Tingkat Risiko:** 🟡 **MEDIUM**
- **Lokasi Kode:** `app/Http/Controllers/AuthController.php` (Baris 157 & 329–335)
- **Bukti Implementasi:**
  ```php
  DB::table('password_reset_tokens')->updateOrInsert(
      ['email' => $email],
      [
          'token' => $token, // Plaintext token disimpan langsung ke DB
          'created_at' => Carbon::now()
      ]
  );
  ```
- **Dampak:** Jika basis data mengalami kebocoran (*database leak/dump*), penyerang dapat langsung menggunakan token reset aktif untuk mengambil alih akun administrator atau pendaftar tanpa batas waktu.
- **Rekomendasi Perbaikan:** Simpan token dalam bentuk hash satu arah:
  ```php
  'token' => hash('sha256', $token)
  ```

### A03:2021 – Injection

#### Evaluasi SQL Injection:
- **Status:** 🛡️ **SECURE / EXCELLENT**
- **Analisis:** Seluruh operasi query Eloquent dan penggunaan klausa `whereRaw` (contoh pada `BatchSeleksiController.php` baris 92) telah menggunakan parameter binding (`?`) secara konsisten. Tidak ditemukan celah konkatenasi string SQL mentah (*raw string concatenation*).

#### Temuan 3.1: Potensi Stored XSS pada Konten Berita
- **Tingkat Risiko:** 🔵 **LOW**
- **Lokasi Kode:** `resources/views/pendaftar/berita_show.blade.php` (Baris 76)
- **Bukti Implementasi:**
  ```blade
  {!! $berita->konten !!}
  ```
- **Dampak:** Konten berita dirender menggunakan unescaped blade tag. Jika akun admin berita dikompromikan, skrip berbahaya (Stored Cross-Site Scripting) dapat disematkan ke dalam konten dan tereksekusi pada browser pengunjung.
- **Rekomendasi Perbaikan:** Terapkan pembersihan HTML (*sanitizer*) seperti `Mews/Purifier` (HTMLPurifier) sebelum konten berita disimpan atau saat dirender.

### A04:2021 – Insecure Design

#### Temuan 4.1: Mekanisme Rate Limiting OTP Dapat Dikelabui via Header User-Agent
- **Tingkat Risiko:** 🟡 **MEDIUM**
- **Lokasi Kode:** `app/Http/Controllers/AuthController.php` (Baris 128 & 313)
- **Bukti Implementasi:**
  ```php
  $throttleKey = 'otp-limit-' . sha1($request->ip() . $request->userAgent());
  ```
- **Dampak:** Penyerang yang terkena rate limit pada satu alamat IP dapat me-reset hitungan pembatasan request hanya dengan mengganti nilai header `User-Agent` di setiap request HTTP, memungkinkan serangan *OTP flooding* (SMS/Email toll fraud).
- **Rekomendasi Perbaikan:** Kunci throttle limit harus didasarkan pada kombinasi `IP` dan `email` tujuan, atau cukup `IP` murni:
  ```php
  $throttleKey = 'otp-limit-' . sha1($request->ip() . '|' . strtolower($email));
  ```

### A05:2021 – Security Misconfiguration

#### Temuan 5.1: Absensi Header Keamanan HTTP pada Middleware Aplikasi
- **Tingkat Risiko:** 🟡 **MEDIUM**
- **Lokasi Kode:** `bootstrap/app.php` (Baris 15–35)
- **Dampak:** Respons HTTP aplikasi belum dilengkapi header pelindung standar browser:
  - `X-Content-Type-Options: nosniff` (mencegah MIME-sniffing)
  - `X-Frame-Options: SAMEORIGIN` (mencegah Clickjacking)
  - `Strict-Transport-Security` (memaksa HTTPS)
  - `Referrer-Policy: strict-origin-when-cross-origin`
- **Rekomendasi Perbaikan:** Daftarkan middleware penambahan header keamanan di `bootstrap/app.php` atau aktifkan konfigurasi header pada level web server (Nginx/Apache).

#### Temuan 5.2: Pengaturan Trust Proxies Terbuka Penuh
- **Tingkat Risiko:** 🔵 **LOW**
- **Lokasi Kode:** `bootstrap/app.php` (Baris 28)
- **Bukti Implementasi:**
  ```php
  $middleware->trustProxies(at: '*');
  ```
- **Dampak:** Semua proxy dipercaya tanpa batasan IP. Jika aplikasi dipindahkan ke lingkungan tanpa reverse-proxy tepercaya, penyerang dapat memalsukan IP asli melalui header `X-Forwarded-For`.
- **Rekomendasi Perbaikan:** Batasi daftar IP proxy tepercaya hanya ke subnet Cloudflare atau IP Load Balancer internal.

### A06:2021 – Vulnerable and Outdated Components

#### Temuan 6.1: Kerentanan Publik pada Dependensi Composer
- **Tingkat Risiko:** 🟠 **HIGH**
- **Bukti Uji:** Eksekusi `composer audit` (terekam pada `/tmp/opencode/composer-audit.json`)
- **Daftar Paket Terdampak:**
  1. **`dompdf/dompdf` (<3.1.6):**
     - `CVE-2026-59943`: Embedded SVG images dapat membocorkan keberadaan file dan direktori pada filesystem lokal (*Information Disclosure*).
     - `CVE-2026-59942`: Denial of Service (DoS) melalui resource exhaustion dari ukuran bitmap gambar besar (*Resource Consumption*).
  2. **Dependensi Framework Laravel:** Terdeteksi beberapa anjuran perbaikan pada komponen Symfony HTTP Foundation, Guzzle, dan League Flysystem.
- **Rekomendasi Perbaikan:** Jalankan pembaruan dependensi teruji:
  ```bash
  composer update dompdf/dompdf --with-all-dependencies
  ```

### A07:2021 – Identification and Authentication Failures

#### Temuan 7.1: Ketiadaan Rate Limiting pada Rute Login Utama
- **Tingkat Risiko:** 🟡 **MEDIUM**
- **Lokasi Kode:** `app/Http/Controllers/AuthController.php` (Baris 34–62)
- **Dampak:** Metode `login()` tidak memanggil `RateLimiter::tooManyAttempts()`. Meskipun formulir frontend dilengkapi Turnstile, penyerang yang mem-bypass frontend dapat melancarkan serangan *credential stuffing / brute force* langsung ke `POST /login`.
- **Rekomendasi Perbaikan:** Tambahkan middleware `throttle:login` (misal 5 percobaan per menit) pada rute login di `routes/web.php`:
  ```php
  Route::post('/login', [AuthController::class, 'login'])->middleware('throttle:5,1');
  ```

#### Temuan 7.2: Kebijakan Kompleksitas Kata Sandi Terlalu Lemah
- **Tingkat Risiko:** 🔵 **LOW**
- **Lokasi Kode:** `app/Http/Controllers/AuthController.php` (Baris 106 & 372)
- **Bukti Implementasi:**
  ```php
  'password' => 'required|string|min:8|confirmed'
  ```
- **Dampak:** Pendaftar dapat mendaftar dengan password lemah seperti `12345678` atau `password`.
- **Rekomendasi Perbaikan:** Gunakan aturan bawaan Laravel `Rules\Password`:
  ```php
  'password' => ['required', 'confirmed', \Illuminate\Validation\Rules\Password::min(8)->letters()->numbers()]
  ```

### A08:2021 – Software and Data Integrity Failures

#### Evaluasi Integritas Upload Berkas:
- **Status:** 🛡️ **SECURE / ACCEPTABLE**
- **Analisis:** Pengecekan pada `app/Http/Controllers/PendaftarController.php` menunjukkan bahwa upload file pendaftar divalidasi dengan whitelist ekstensi/mime (`mimes:pdf,jpg,jpeg,png,webp`), batasan ukuran file, dan nama file di-generate secara acak.
- **Rekomendasi Tambahan:** Pastikan direktori `public/storage` memiliki konfigurasi web server yang melarang eksekusi file skrip (contoh: `.php`, `.phtml`, `.cgi`).

---

### A09:2021 – Security Logging and Monitoring Failures

#### Temuan 9.1: Tidak Adanya Pencatatan Percobaan Autentikasi Gagal
- **Tingkat Risiko:** 🔵 **LOW**
- **Lokasi Kode:** `app/Http/Controllers/AuthController.php`
- **Dampak:** Sistem mencatat aktivitas penting admin melalui `ActivityLogController`, namun kegagalan login dan serangan brute-force berulang tidak direkam ke basis data, menyulitkan deteksi insiden (*incident forensics*).
- **Rekomendasi Perbaikan:** Tambahkan penulisan log saat autentikasi gagal:
  ```php
  Log::warning("Percobaan login gagal untuk email: {$request->email} dari IP: {$request->ip()}");
  ```

---

### A10:2021 – Server-Side Request Forgery (SSRF)

#### Evaluasi Permintaan Eksternal:
- **Status:** 🛡️ **SECURE**
- **Analisis:** Seluruh request HTTP keluar (*outbound requests*) dalam aplikasi (seperti verifikasi Cloudflare Turnstile pada `https://challenges.cloudflare.com/turnstile/v0/siteverify` dan integrasi Google Sheets) mengarah ke endpoint yang telah di-hardcode (*static whitelist*). Tidak ada parameter input pengguna yang di-fetch secara dinamis oleh cURL / Guzzle.
